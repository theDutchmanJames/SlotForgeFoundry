# Code audit, 21 November 2026

Seven read-only reviews covered the whole app (about 50,000 lines in 164 files):
- `main.js`, in two halves;
- the geometry engine and STL editing;
- track generation;
- the Track Planner and print kit;
- the library, imports and forms;
- the 3D view and drawing tools.

Each finding was checked against the code before it was fixed. Fixes are listed by area; the last sections list what was found to be by design and what is left open.

## Fixed

### Data loss and wrong saves
- **New design / Open STL overwrote the open Library part.** Both kept the link to the STL part that was open, so Save to Library replaced that part with the unrelated model. Both now drop the link (`main.js`, `new-design` and `importFile`).
- **New layout overwrote the open Library layout.** The Planner's New layout kept the saved layout's id; Save to Library then replaced it. The id is now dropped (`planner-workspace.js`).
- **Renaming a layout rewrote the whole record.** A planner save made while the rename dialog was open was lost. Rename now only changes the name, inside one write (`renameLayout` in `library-database.js`).
- **Saving an STL part was never persisted.** The new link was changed in place, so after Undo or a reload the next save made a duplicate. The link is now saved, and found again through the model's source, which every Undo step shares (`savedStlParts` in `main.js`).
- **A pack save left a stale revision behind.** After Undo or a reload, every later save of that piece failed with "changed in another window". The new revision is now saved, and the latest one this window wrote is used (`savedPackRevisions` in `main.js`).
- **Apply to collection was not atomic.** The piece kept the new rules when the pack refused them, and from then on disagreed with its pack. It is now rolled back, together with its undo step.
- **A project that failed to reopen at start was overwritten by the next autosave.** A copy is now kept, and Settings offers "Download the last project" (`keepUnopened`, `readUnopened` in `project.js`).
- **The same for a Planner layout that failed to reopen.** A copy is kept and opened again the next time the Planner starts with an empty layout.
- **A restored backup could bring back a pack at an old revision.** A window still holding that revision could then save over the restored pack. Restored packs now get a revision no window can hold (`replaceLibrary(..., { restore: true })`).

### Things that broke or hung
- **Deleting the open piece's pack sent the pack rail into an endless reload loop.** The rail now remembers a missing pack and says so; Apply keeps the change in the project, now unlinked. Deleting the pack also saves the unlinked project.
- **Library page, Open on an STL part did nothing visible.** The page stayed over the workspace; it now closes.
- **Rebuild with my edits could leave you on the pack piece.** If the part was gone or its edits no longer fitted, the piece stayed open. The project that was open now comes back, undo history included.
- **One linked piece that could not follow its pack stopped the whole Planner from opening.** That piece now keeps its own copy, and the message says so.
- **Re-editing a surface-brush step failed whenever a later step was switched off.**
- **Switched-off sketches and features were still offered as inputs to new steps.**
- **A malformed switched-off step in a saved file crashed with a raw TypeError.** Every step is now checked.
- **Plate dialog crashed with no part selected** when a field was cleared.
- **Settings left two nav buttons highlighted** after a redraw.
- **Planner could be opened twice by a double click.**

### Wrong behaviour or messages
- **Switching off or deleting a step, Use this plate and Rename dropped a pending tool edit.** They also blamed "a later step" when another calculation was simply still running. They now apply the edit first and give the real reason.
- **Escape in a tool's field discarded the whole tool.** It now only leaves the field; the next Escape closes the tool.
- **Ctrl+S, Ctrl+O, Ctrl+Z and Ctrl+Y could run alongside another action.** They now use the same guard as a click.
- **Enter on Cancel in a delete confirmation deleted the item.** Enter now only confirms from the name field.
- **Pack rules dialog title was not HTML-escaped** (XSS through a pack name).
- **Restore warning left out layouts and STL parts.** It now says when they will be replaced too.
- **Settings number fields:**
  - a cleared field fell back to factory values, or to 0 for margin, spool price and spare braid;
  - choosing a printer overwrote a margin of 0.
  Fields now fall back to the last value, and the margin is kept.
- **Split with `axis: 'X'` in a saved file** exported the whole part as "additions only". The axis is now read case-insensitively.
- **A corner over 355° with end connectors** failed with a misleading pocket message. It is now refused with a clear reason.
- **The two connector-placement checks** used different tolerances at the road edge.
- **The keeper turning tool** was in the print kit, but missing from parts.csv and the shopping list.
- **DXF with a damaged unit header** was imported as millimetres; it is now refused.
- **Thumbnail cache key** left out a freeform piece's shape.

### Planner caching and the worker
- **The Planner's in-memory piece cache grew without limit.** It now keeps the 80 most recently used.
- **A background build stored its piece under the old plate** if the plate changed meanwhile. The plate is now fixed for each build.
- **A click waiting on a piece the background had already started showed no Cancel.** It now does.
- **Planner pieces waited for the open project to be rebuilt after a cancel.** That restore is no longer needed for them.
- **Device cache:** one failed open no longer disables it for the session. It is off in the dev server, where the generator ID would go stale.
- **While previewing an added STL model, the engine parsed it again on every keystroke.**
- **An empty part could make the 3D view's depth range NaN.**
- **In the sketch dialog, Undo also switched the workplane back.**

## Checked and kept as designed
- **A centre line on 1 or 3 lanes is left out.** An existing test asserts this deliberately.
- **Kerbstones on a side without a border are skipped.** The defaults rely on this, and stored pieces would break.
- **Collection `clipClearance` limits.** A profile without a fit version takes the piece's version, so the stricter limit cannot be applied at pack level.

## Open (not changed)
- **Section view redraw on every live preview** (`viewport.js` `setParts` → `clearSection`). The section briefly shows the whole model until it is rebuilt. The section meshes borrow the part meshes, so keeping them through a redraw needs a careful rework.
- **Sketch loops with no area, or crossing themselves, are accepted.** A zero-area loop fails later with "no printable area"; a bow-tie is filled as two triangles.
- **Shopping list lanes.** Lanes are summed by position in each piece. A run joined end-to-end in reverse (Snap ends), or pit and lane-change pieces, can mix lane 1 and lane 2 lengths. The total braid length is right.
- **Specials following a pack.** A special that follows its pack keeps its own special settings. Pit offset and chicane radii are not re-derived from the new rules.
- **The STL repair session is lost after Cancel** in the STL review dialog. Reopen the STL to review it again.
- **Smaller items:**
  - very small print segments are accepted;
  - the curve segment-length message is generic;
  - the software renderer can drop kerb paint on graded planner pieces;
  - a reused mesh can keep its old edge-line decision.
